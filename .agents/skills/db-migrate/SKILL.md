---
name: db-migrate
description: 'Strict Goose migration workflow for packages/db/migrations: write timestamped Up/Down SQL, apply local/test migrations, and regenerate Kysely types.'
disable-model-invocation: true
---

Use this workflow for any schema change in `packages/db/migrations/`:

1. Create a new flat migration file named `YYYYMMDDHHMMSS_<domain>_<change>.sql`.
2. Keep one concern per file. Split schema creation, backfills, indexes, policies, and triggers when they are separate concerns.
3. Write a Goose `Up` section and a matching `Down` section.
4. Wrap multi-statement blocks in `-- +goose StatementBegin` and `-- +goose StatementEnd`.
5. Put the SQL change in the migration file, not in `packages/db/src/types/database.ts` — that file is generated by `kysely-codegen` and must never be edited by hand.
6. Apply to the local dev database (port 5434) and regenerate Kysely types. `DATABASE_URL` has no fallback — set it explicitly:

   ```bash
   export DATABASE_URL="postgresql://postgres:postgres@127.0.0.1:5434/hominem"
   just db migrate    # apply migrations
   just db codegen    # regenerate packages/db/src/types/database.ts
   ```

7. Apply to the test database (port 4433) so tests exercise the new schema:

   ```bash
   just db migrate test
   ```

8. Confirm migration state with `just db status` / `just db validate`. `just db validate` applies migrations then fails if any are pending — it is what CI runs (`just db validate test`). Use `just db rollback` (or `just db rollback test`) to test a `Down` section.
9. Run `just db lint` on the migration files if CI's unqualified-drop check might trip (drops in `app`/`auth`/`ops` must be schema-qualified).
10. Review the resulting migration and the generated type diff before moving on.

The repo convention is flat, chronological Goose migrations with clear suffixes for meaning, for example `20260709234400_create_app_calendar_import_tables.sql`.

If the command fails:

1. Check that Docker is running and the relevant Postgres containers are up (local on port 5434, test on port 4433).
2. Check that `DATABASE_URL` is set — `just db migrate` and `just db codegen` require it; there is no fallback URL.
3. Check that the migration SQL uses Goose markers correctly and that `Up` and `Down` are both present.
4. Run `just db status` to inspect the current migration state before retrying.
